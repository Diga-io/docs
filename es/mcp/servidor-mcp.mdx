Usa el servidor Model Context Protocol (MCP) alojado por Diga para crear y gestionar agentes de voz desde asistentes de IA y herramientas de desarrollo compatibles.

<Note>
Esta página explica cómo conectar un asistente **a Diga**. Para que un agente de voz de Diga acceda a un servidor MCP externo durante una llamada, consulta [Integraciones MCP](../build/integraciones/integraciones-mcp).
</Note>

## Requisitos previos

Antes de comenzar, necesitas:

- Una cuenta de Diga que pertenezca a un proyecto
- Un cliente MCP que admita OAuth en servidores remotos, o una API key de Diga de ese proyecto (la crean los administradores)
- Un cliente MCP compatible con servidores remotos mediante Streamable HTTP

Si todavía no tienes una clave, sigue los pasos para [crear una API key](../plataforma/api-keys#crear-una-api-key). Crea una clave restringida con solo los permisos que necesite tu asistente.

## Qué puedes hacer

El servidor MCP de Diga convierte las operaciones de la API de Diga en herramientas que tu asistente puede descubrir y utilizar. Según los permisos de tu API key, puedes usar lenguaje natural para:

- Crear, actualizar, publicar, listar y consultar agentes de voz y sus versiones
- Crear llamadas y consultar sus detalles, mensajes, grabaciones, logs y trazas
- Crear y mantener bases de conocimiento a partir de texto, URLs y archivos
- Gestionar números de teléfono, voces, integraciones, webhooks y flujos
- Consultar miembros, uso, facturación y otros recursos del proyecto

Tu cliente MCP muestra las herramientas exactas disponibles, incluida la descripción y los parámetros requeridos de cada una.

## Elige cómo autenticarte

El servidor MCP de Diga acepta dos tipos de credenciales.

| Método | Ideal para | Cómo se elige el proyecto |
|---|---|---|
| **Inicia sesión con tu cuenta de Diga (OAuth)** | Un asistente personal, si tu cliente MCP admite OAuth en servidores remotos | Lo eliges en cada sesión y puedes cambiarlo cuando quieras |
| **API key de proyecto** | Configuraciones compartidas, automatizaciones y clientes sin soporte de OAuth | Fijo: el proyecto donde creaste la clave |

Ambos dan acceso a las mismas herramientas. Una sesión OAuth tiene los permisos de tu rol en el proyecto; una API key, los permisos que le asignaste.

## Inicia sesión con tu cuenta de Diga (OAuth)

Añade el servidor sin ningún header de autenticación:

```bash
claude mcp add --transport http diga https://mcp.diga.io/mcp
```

Tu cliente se registra en el servidor de autorización de Diga y abre una ventana del navegador. Inicia sesión con tu cuenta de Diga y aprueba el acceso.

### Selecciona un proyecto

Tu cuenta puede pertenecer a varios proyectos, así que una sesión OAuth empieza sin ninguno. La primera llamada a una herramienta devuelve un error con la lista de proyectos a los que perteneces. Pide a tu asistente que elija uno:

> Usa el proyecto de Diga Acme.

Esto ejecuta la herramienta `diga_select_project`. La elección se guarda durante 24 horas y se aplica al resto de llamadas de la sesión. Pídelo de nuevo cuando quieras cambiar de proyecto.

## Conecta con una API key de proyecto

Tu cliente MCP se conecta a Diga mediante Streamable HTTP y envía tu API key con cada solicitud.

| Ajuste | Valor |
|---|---|
| Nombre del servidor | `diga` |
| URL del servidor | `https://mcp.diga.io/mcp` |
| Header de autenticación | `x-api-key: <DIGA_API_KEY>` |

<Info>
Una API key pertenece al proyecto de Diga donde la creaste. Ese proyecto es la empresa que gestiona el asistente. Para trabajar con otra empresa, crea o copia una clave de ese proyecto y sustituye la clave en la configuración de tu cliente MCP.
</Info>

## Conecta tu cliente MCP

Elige tu cliente y sustituye `<DIGA_API_KEY>` por tu API key completa de Diga.

<Tabs>
  <Tab title="Cursor">
    Abre **Cursor Settings → MCP → Add new global MCP server** y añade:

    ```json
    {
      "mcpServers": {
        "diga": {
          "url": "https://mcp.diga.io/mcp",
          "headers": {
            "x-api-key": "<DIGA_API_KEY>"
          }
        }
      }
    }
    ```
  </Tab>

  <Tab title="Claude Desktop">
    Abre **Settings → Developer → Edit Config** y añade:

    ```json
    {
      "mcpServers": {
        "diga": {
          "url": "https://mcp.diga.io/mcp",
          "headers": {
            "x-api-key": "<DIGA_API_KEY>"
          }
        }
      }
    }
    ```

    Reinicia Claude Desktop después de guardar el archivo. La disponibilidad de headers para servidores remotos puede variar según la versión de Claude Desktop.
  </Tab>

  <Tab title="Claude Code">
    Ejecuta:

    ```bash
    claude mcp add --transport http diga \
      --header "x-api-key: <DIGA_API_KEY>" \
      https://mcp.diga.io/mcp
    ```
  </Tab>

  <Tab title="Codex">
    Añade el servidor a `~/.codex/config.toml`:

    ```toml
    [mcp_servers.diga]
    url = "https://mcp.diga.io/mcp"
    bearer_token_env_var = "DIGA_API_KEY"
    ```

    Después, define la variable de entorno antes de iniciar Codex:

    ```bash
    export DIGA_API_KEY="<DIGA_API_KEY>"
    ```

    Codex envía este valor como `Authorization: Bearer <DIGA_API_KEY>`, un formato que también acepta el servidor MCP de Diga.
  </Tab>

  <Tab title="Otros clientes">
    Configura un servidor remoto Streamable HTTP con estos valores:

    ```json
    {
      "name": "diga",
      "url": "https://mcp.diga.io/mcp",
      "headers": {
        "x-api-key": "<DIGA_API_KEY>"
      }
    }
    ```
  </Tab>
</Tabs>

<Warning>
Nunca incluyas una API key en la URL del servidor ni la subas al control de versiones. Las URLs pueden aparecer en el historial, los logs del proxy y las analíticas. Usa variables de entorno cuando tu cliente MCP lo permita.
</Warning>

## Verifica la conexión

Después de guardar la configuración, reinicia o recarga tu cliente MCP. Comprueba que aparece un servidor llamado **diga** y que sus herramientas están disponibles.

Empieza con una solicitud de solo lectura, por ejemplo:

> Lista mis agentes de Diga.

Tu cliente debería pedir confirmación antes de ejecutar una herramienta si sus ajustes de permisos así lo requieren.

## Solución de problemas

<AccordionGroup>
  <Accordion title="Una herramienta dice que no hay proyecto seleccionado">
    Has iniciado sesión con OAuth, y esas sesiones empiezan sin proyecto activo. Pide a tu asistente que elija uno de los proyectos que aparecen en el mensaje de error; la elección dura 24 horas.
  </Accordion>

  <Accordion title="No se abre el inicio de sesión en el navegador">
    Tu cliente MCP no admite OAuth en servidores remotos. Conéctate con una API key de proyecto.
  </Accordion>

  <Accordion title="El servidor devuelve 401 Unauthorized">
    Confirma que has copiado la API key completa y que el cliente la envía como `x-api-key` sin el prefijo `Bearer`. Si usas el header `Authorization`, su valor debe ser `Bearer <DIGA_API_KEY>`.
  </Accordion>

  <Accordion title="Una herramienta devuelve 403 Forbidden">
    La API key es válida, pero no tiene permiso para usar ese recurso. Actualiza las restricciones de la clave en **Ajustes → Proyecto → API Keys** o usa otra clave restringida con el permiso necesario.
  </Accordion>

  <Accordion title="El asistente muestra una empresa incorrecta o ningún recurso">
    La API key determina el proyecto. Sustitúyela por una clave creada en el proyecto de Diga correcto y reinicia el cliente MCP para que vuelva a cargar la configuración.
  </Accordion>

  <Accordion title="El cliente no puede conectarse al servidor">
    Verifica que la URL sea exactamente `https://mcp.diga.io/mcp` y que el cliente admita servidores MCP remotos mediante Streamable HTTP. Algunos clientes necesitan reiniciarse después de cambiar la configuración.
  </Accordion>
</AccordionGroup>

## Recomendaciones de seguridad

- Crea una API key diferente para cada cliente MCP y entorno
- Concede solo los permisos de lectura o escritura que necesite el asistente
- Revisa las llamadas a herramientas antes de aprobar acciones que modifiquen o eliminen recursos
- Rota la clave inmediatamente si queda expuesta
